# CortexView explainer video (Manim)

A ~90-second, 1920×1080 explainer for CortexView, built with **Manim Community Edition** (tested with 0.22.0 on Windows 11, Python 3.12). It needs no LaTeX and no API keys. The video renders silent; the narration for ElevenLabs is in `scripts/`.

```
video-manim/
├── CortexView_Manim_Video_Prompt.md   the brief
├── animation/
│   ├── cortexview_video.py   scenes: CortexViewFull (whole video) and S1Hook … S6Closing
│   ├── components.py         images from the phantom, pixel grids, legends, formula text, pipeline nodes
│   ├── colors.py             theme and type; tissue colors come from shared/layers.json
│   ├── config.py             timeline: segment lengths and beats (edit here to re-time)
│   ├── phantom.py            NumPy port of the web prototype's synthetic phantom + its metrics
│   ├── render.py             preview / final / single scene / add voiceover
│   ├── tests/test_phantom_port.py   diffs phantom.py against the original phantom.ts (needs Node ≥ 23.6)
│   ├── scripts/              voiceover_clean.txt, voiceover_timed.md, pronunciation_notes.md
│   └── assets/README.md
└── output/                   rendered MP4s (gitignored, like every output/ folder in this repo)
```

## What the video shows, and how accurate it is

| Time | Scene | Content |
|---|---|---|
| 0:00 | S1Hook | An image is a grid of numbers; the numbers become labels |
| 0:10 | S2Layers | The synthetic slice, its label map, and the five layers (labels 1, 2, 3, 4, 10) |
| 0:25 | S3Measure | A = N·s² for the lesion (2,211 px × 0.56² mm² ≈ 693 mm²); largest boundary distance ≈ 32.8 mm |
| 0:43 | S4Design | "Generative where it helps, deterministic where it matters", shown as the design |
| 1:00 | S5Status | Works today / in progress / planned |
| 1:15 | S6Closing | Layered slice with measurement pins; title |

- **Every image is the synthetic phantom** that the web prototype shows (`phantom(440, 0, mkRnd(7))`, 0.56 mm/px). It's labelled on screen as *generated by code, not a patient*. The port matches the TypeScript exactly: same labels, image values within 1e-6, and identical metrics.
- **Every number is computed**, not typed in: `phantom.measure()` uses the prototype's formulas (`buildPhantomSlice()`).
- **The image model is shown as in development.** The current plan is an edit LoRA on **FLUX.2 klein base-4B** (Apache-2.0), trained locally on the RTX 5060 laptop. `scripts/lora/train_klein4b_edit.yaml` says it "replaces the Lightning 9B setup". On 2026-10-11 the base model was still downloading and nothing was trained. In the design the model's job is the illustration's look, not segmentation. Segmentation is classical code (`backend/cortexview/segment.py`).
  - `docs/PROJECT_MAP.md` still describes the earlier 9B-on-Lightning plan. The video follows the newer 4B config. Narration says only "the style model", so it holds either way; only the scene-5 node names the size (`cortexview_video.py`, `seg_status`).
- The "illustration" in scene 4 is the prototype's code-shaded rendering, captioned as a mock-up. It is not model output.
- Upload in the web app is shown as *planned*: `backend/` has the DICOM → segmentation library (tested), but no API server yet.

## Setup

Manim needs Python 3.10–3.13 and ffmpeg. On Windows the PyPI wheels include Cairo and Pango, so nothing else is needed. LaTeX is **not** required: formulas use `MarkupText` in Cambria. The fonts used are Segoe UI, Cambria and Consolas, which ship with Windows. On macOS or Linux, change `SANS`, `SERIF` and `MONO` in `colors.py` to fonts you have.

Keep the venv and Manim's cache **outside the repo**, because the repo is synced by OneDrive:

```powershell
# from the repo root, PowerShell
uv venv --python 3.12 $HOME\cortexview_video\.venv          # or: py -3.12 -m venv $HOME\cortexview_video\.venv
uv pip install --python $HOME\cortexview_video\.venv\Scripts\python.exe manim pytest
$py = "$HOME\cortexview_video\.venv\Scripts\python.exe"
& $py -m manim --version                                      # Manim Community v0.22.0
ffmpeg -version                                               # needed for `mux`; Manim itself bundles PyAV
```

`render.py` writes Manim's cache to `$env:CORTEXVIEW_MEDIA` (default `~\cortexview_video\media`) and copies finished videos into `video-manim/output/`.

## Render

```powershell
$py = "$HOME\cortexview_video\.venv\Scripts\python.exe"

# low-res check of one scene (480p15), e.g. while editing
& $py video-manim\animation\render.py scene S3Measure

# preview of the whole video: 1280x720 @ 30 fps  -> video-manim\output\cortexview_preview.mp4
& $py video-manim\animation\render.py preview

# final: 1920x1080 @ 60 fps  -> video-manim\output\cortexview_final.mp4
& $py video-manim\animation\render.py final
```

Plain Manim works too. For example, a quick 480p15 run of the whole video that opens when done:

```powershell
& $py -m manim -pql --media_dir $HOME\cortexview_video\media video-manim\animation\cortexview_video.py CortexViewFull
```

Measured on this machine (RTX 5060 laptop; Manim's Cairo renderer is CPU-only): 480p15 took about 1.5 min. See the bottom of this file for the preview and final times.

## Add the voiceover

1. Paste `scripts/voiceover_clean.txt` into ElevenLabs (see `scripts/pronunciation_notes.md` for settings). Export MP3 or WAV.
2. Mux it with the final video. This uses local ffmpeg; the video stream is copied, not re-encoded:

```powershell
& $py video-manim\animation\render.py mux C:\path\to\narration.mp3            # -> output\cortexview_final_voiceover.mp4
& $py video-manim\animation\render.py mux C:\path\to\narration.mp3 --offset 0.3   # delay the voice by 0.3 s
```

## Re-timing to a recorded voice

All timing is in `config.py`:

- `SEGMENTS` sets each scene's length; they add up to the video length.
- `BEATS` sets when each visual event starts, in seconds from the start of its scene.

The scenes wait for these marks. If an animation runs past the next beat, the render logs `beat '…' starts …s late`. Keep `scripts/voiceover_timed.md` in step when you change the timing.
